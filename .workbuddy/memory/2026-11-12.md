# 2026-11-12

## 项目梳理：vue-element-admin-site

- VuePress `0.14.9` + webpack 3 的纯文档站，脚本只有 `npm run dev` / `npm run build`（见 `package.json`），站点端口 8080，`base: '/vue-element-admin-site/'`，三语 locale（`/`、`/zh/`、`/es/`）。
- 本机 Node `v22.22.2`：webpack 3 依赖 MD4 哈希，**冷启动编译**会报 `ERR_OSSL_EVP_UNSUPPORTED`，必须加 `NODE_OPTIONS=--openssl-legacy-provider`。热缓存时即使不加也能过，容易误判。
- `vuepress/lib/dev.js` 关键事实：Windows 下 host 默认 `localhost`（只绑 `[::1]`），Linux/macOS 默认 `0.0.0.0`；端口由 `portfinder` 顺延；**实际占用 port 和 port+1**（后者是 ws 服务），所以探测端口必须成对探测。

## 新增：start.bat / start.sh 一键启动

- 功能：环境检查（node/npm）→ Node 17+ 自动加 legacy provider → 缺依赖自动 `npm install` → 成对探测空闲端口 → 后台轮询站点就绪后再打开浏览器 → 前台跑 `npm run dev` → 区分正常退出与异常退出。
- **start.bat 必须存成 GBK(cp936) + CRLF**：UTF-8 保存会导致 cmd 行解析错乱（表现为 `'else' 不是内部或外部命令` 等），加 `chcp 65001` 也救不回来。改完用 PowerShell 转码：
  `[IO.File]::WriteAllText($p, ($c -replace "`r?`n","`r`n"), [Text.Encoding]::GetEncoding(936))`
- 端口探测踩坑：
  - `net.TcpClient.Connect('127.0.0.1',port)` 探测不到 `[::1]` 监听的服务 → 用 `curl`（`--noproxy *`）或 node `listen(port,'::1')`。
  - 沙箱/工具环境带 `http_proxy`，curl 探测必须加 `--noproxy '*'`，否则本地端口会被代理返回 502。
  - `Invoke-WebRequest` 打 VuePress dev 页面会超时（SPA 资源多），不适合做就绪探测。
- 已验证：冷/热启动均成功，三语页面 200，浏览器在站点就绪同秒自动打开，8080/8081 被占用时正确顺延到 8082 且提示地址与实际一致。
